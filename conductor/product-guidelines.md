# Product Guidelines

本書は Copy Pretty Git Log の利用者向け文言に関する基準を定める。
実装の詳細設計は `tech-stack.md`、作業手順は `workflow.md` を参照せよ。

## 1. 製品の位置づけ

- **カテゴリ**: JetBrains Marketplace の Utilities 相当。
  作業効率ツールであり、Git の GUI そのものではない。
- **想定される場面**: コミット一覧を Issue・Pull Request・レビューコメント・
  リリースノートへ貼り付ける前段で、書式を整えたテキストを得る。
- **言わないこと**: バージョン管理の推奨、コミット運用の指導、
  開発手法の批評。行動を促す表現は用いない。

## 2. トーン

- **日本語**: 常体。断定的に記述する。
- **英語**: 常体。命令形を許容する（Git ログ上の操作手順のように、
  画面上で行う操作を説明する箇所）。
- **普遍禁止**:
  - 過度な熱意。「強力な」「完璧な」「劇的に改善」
  - 未検証の断定。数値やベンチマークを揭載しない。
  - 攻撃的なマーケティング表現。「今すぐ試そう」「体感せよ」

## 3. 文言の言語規定

本製品では 2 種類の audience が混在する。それぞれの言語を固定する。

| 対象 | 言語 | 根拠 |
|---|---|---|
| `README.md` | 英語・日本語の併記（同一内容の 2 ブロック） | 現行の構造を維持する。Marketplace の description には英語部分のみが抽出される |
| `CHANGELOG.md` | 英語のみ | 現行の Keep a Changelog 準拠を維持する |
| `plugin.xml` の description | 英語のみ | `README.md` の `<!-- Plugin description -->` 区間から自動抽出される |
| ソースコードの識別子・KDoc | 英語 | 現行の `CommitProperty.AUTHOR_NAME` 等の命名に合わせる |
| GitHub Issue・Pull Request・コミットメッセージ | 日本語 | `AGENTS.md` のコミット規約が日本語を必須化している |
| Conductor 配下の文書 | 日本語 | 本書と同じとする |

**禁止事項**: 日本語の文書に英字のみの説明を混在させること。逆も同様である。

## 4. UX 原則

本プラグインの UX 表面積は 2 つだけである。

### 4.1 コンテキストメニューアクション

- 名称は `Copy Pretty Git Log` とする。大文字小文字の変更は承認しない。
- コミットが 1 つ以上選択されていない場合は何もしない。
  ダイアログを起動しない。操作 1 回で完結させる。

### 4.2 設定画面

- 3 項目（カスタムパターン・逆順・時刻書式）のみを持たせる。
- 補助テキストの増設や条件分岐の追加はしない。
- 設定の保存は IntelliJ プラットフォームの apply / reset に委ねる。
  自前の保存ボタンは設けない。

### 4.3 汎用

- 日本語ロケールを第一級として扱う。UI 文字列はリソースバンドルに分離し、
  実行時ロケールに従う。
- 設定値の変更は次回アクション実行時から反映する。実行中に動的に変動させない
  （冪等性を保つ）。

## 5. 変更の記録

- `CHANGELOG.md` の `## [Unreleased]` 配下に追記する。
- 節は Keep a Changelog の標準区分（`Added` / `Changed` / `Deprecated` /
  `Removed` / `Fixed` / `Security`）を用いる。
- **プラットフォーム対応を変更する場合は必ず `### Changed` に
  `Supported in IntelliJ <バージョン>` の形式で記載する。**
  これは本プロジェクトにおいて利用者が最も注目する情報である。
